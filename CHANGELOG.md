# Changelog

## [Unreleased]

### Added

- Initial release: `Scry.Engine.Couchbase` -- a real `Scry.Core.EngineBehaviour` implementation over Couchbase, via `req` rather than a dedicated client. Replaces `scry_document`'s own in-memory reference implementation (`Scry.Document.Executor`) with genuine bucket/scope/collection-and-N1QL-backed `DEEP`/`PARENT`/`SIBLINGS`/`ANCESTORS` execution against a *third* real document store, after `scry_engine_mongodb_driver`/`scry_engine_couchdb` -- and `scry_reldoc`'s own long-deferred storage adapter, closing the last item impl_spec.md §6 had named but not shipped.
  **No dedicated driver, confirmed not assumed**: no official Couchbase SDK covers Elixir or Erlang at all; every community option found (`gauc`, two `cberl` forks, `couchie`) is confirmed multi-year stale (2017-2023). Couchbase's own Query Service exposes a plain HTTP N1QL endpoint (`POST :8093/query/service`) -- the identical "no client-specific protocol to speak" situation `scry_engine_elasticsearch`/`scry_engine_couchdb`/`scry_engine_loki`/`scry_engine_influxdb` already resolved with `req`, applied here for the same reason.
  **Bucket + scope, fixed at `Conn.open/1` time; collection-per-tree-key, joined with `__`**: Couchbase's own data model nests one level deeper than MongoDB/CouchDB (bucket > scope > collection > document) -- `bucket`/`scope` play the fixed-context role `scry_engine_mongodb_driver`'s own `database` plays, and one real collection per tree-position key (segments joined with `__`, not `.`: Couchbase disallows a literal `.` in collection names, confirmed directly, the identical restriction `scry_engine_couchdb`/`scry_engine_arangodb` already found) lives inside it.
  **Two real N1QL REST findings**: a `$name` placeholder binds to a real top-level `"$name"` request field, not a nested wrapper -- an earlier draft's `"$args"`-wrapped map silently left every placeholder unbound, caught by a real, reproduced test failure; and an application-level query failure (an unbound parameter, a missing keyspace) can arrive inside a real HTTP `200` whose body still carries both `"results": []` and a fatal `"errors"` array -- unlike every other REST-backed adapter in this family, all of which signal failure via a non-2xx status, so `Conn.n1ql/3` checks for `"errors"` before trusting a 200's own `"results"` key.
  **A real, load-bearing consistency finding**: Couchbase's own default N1QL scan consistency (`not_bounded`) is genuinely eventually-consistent against its own indexer -- confirmed directly, a document inserted immediately before an unqualified `SELECT` came back with zero rows -- so `Conn.n1ql/3` always forces `scan_consistency: "request_plus"`. A second, version-specific finding: Couchbase Server 7.6's own index-free full-collection-scan capability means this package issues no index-management calls at all, unlike older Couchbase releases. A third: even under `request_plus`, a freshly-created collection can briefly 12003 against the Query Service's own metadata cache after the Cluster Manager's own creation call already returned `200` -- `Conn.create_collection/2` polls a cheap read until the collection is genuinely queryable before returning.
  **No pushdown at all**, the identical posture `scry_engine_mongodb_driver`/`scry_engine_couchdb` already establish: every `WHERE`/`GROUP BY`/aggregates/`HAVING`/`DISTINCT`/`ORDER BY`/`LIMIT`/`OFFSET`/projection applies generically via `Scry.Core.QueryOps.run_flat/3`, never translated into N1QL.
  **A missing collection is an error, matching the reference**, the identical divergence-from-MongoDB `scry_engine_couchdb` already states, confirmed again here: a Couchbase collection must be explicitly created before anything can be read from it. No document-identity field ever needs stripping either, unlike `_id`/`_rev` in its siblings: this package only ever projects `d.*`, never `META(d).id`.
  **Parity tested against the reference**: AGENTS.md's own "Parity between multiple implementations" rule applied directly, reusing `scry_document`'s own fixture verbatim -- three of its own multi-row cases needed an explicit `ORDER BY title` added, since (unlike CouchDB's own coincidentally-stable sequential document IDs) Couchbase's `KEY UUID()`-generated keys give no insertion-order stability at all without one. A separate suite, `test/scry/engine/couchbase/reldoc_test.exs`, is this package's own distinct contribution beyond parity: it proves `scry_reldoc`'s own correlated-nested-`SELECT` + `PARENT` composite semantics hold against a real backend, not just the in-memory reference.
